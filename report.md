# Report

## Track

Выбранный трек:

```text
A - выбрал трек, так как обучал модель без GPU на MacBook Air M4, поэтому использовал только CPU
```

## Что реализовано

- [+] dataset.py
В dataset.py реализована загрузка manifest-based датасета, фильтрация по split, поддержка max_samples, открытие изображений в RGB и возврат примеров в формате MathVQASample.
- [+] processor.py
В processor.py реализованы обработка изображений, построение prompt с image-токенами, токенизация, формирование input_ids, attention_mask, labels, маскирование prompt-токенов через IGNORE_INDEX и padding батча.
- [+] model.py
В model.py реализованы VisionToTextAdapter, вставка visual embeddings в позиции image-токенов, базовый MathVLM.forward, generate и заморозка backbones.
- [+] train.py
В train.py реализован smoke-training loop для Track A: загрузка конфига, seed, dataset, processor, tiny CPU-модели, DataLoader, finite loss check, gradient accumulation, max_steps, fast_train и сохранение checkpoint при наличии пути.
- [+] benchmark.py
В benchmark.py реализованы prompt для evaluation, парсинг multiple-choice ответов, подсчёт overall accuracy и accuracy по subject. Для toy benchmark также добавлен простой deterministic symbolic baseline, который решает часть простых текстовых математических задач. Это не полноценная VLM, а CPU-friendly baseline для проверки работоспособности пайплайна. Не стал докручивать до идеала, так как судя по тексту задания, цель была именно в том, чтобы пайплан просто отрабатывал корректно, а не в выходе на наилучший результат по тестам.

## Анализ ошибок

Приведите 3 ошибки модели:

Toy-dev набор очень маленький, поэтому ошибок получилось немного. Главное ограничение текущего решения в том, что оно не является настоящей визуально языковой моделью и не умеет полноценно извлекать сложную информацию из изображения.
1. Ошибка на задаче с графиком: простой решатель по правилам не умеет надёжно читать значения со столбцов, осей и подписей на изображении.
2. Ошибка на задачах с мелкими визуальными деталями: числами на картинке, подписями, углами, длинами отрезков или положением объектов.
3. Ошибка на многошаговых задачах, то есть если сначала нужно понять картинку, затем выполнить несколько математических действий и только потом выбрать вариант, модель не справляется. 


## Комментарии

Что оказалось самым сложным, что бы вы улучшили?

Самым сложным было связать текстовую и визуальную части решения. Нужно было правильно добавить токены изображений, получить визуальные признаки, перевести их в размерность текстовой модели и вставить в нужные места среди текстовых эмбеддингов.
